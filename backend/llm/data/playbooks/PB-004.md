# Playbook PB-004: Prompt Injection Containment & Guardrail Enforcement

## Purpose
Procedures to identify, contain, and remediate direct and indirect prompt injection attacks against LLM applications, autonomous agents, and RAG pipelines.

## Detection Indicators
- Guardrail alerts (e.g., Llama Guard, NeMo Guardrails, custom semantic classifier) flagging jailbreak patterns, system prompt overrides, or boundary bypasses.
- Unusual model responses containing internal system prompt text, API keys, or forbidden instructional steps.
- Inputs containing payload markers such as `[SYSTEM]`, `Ignore previous instructions`, `DAN:`, base64/hex encoded instructions, or indirect injection markers embedded in retrieved documents.

## Triage Steps
1. Capture the exact input prompt, system prompt version, retrieved context chunks (if RAG), and the model's raw completion.
2. Determine whether the injection was direct (user supplied in chat) or indirect (retrieved from an external untrusted document/URL/email).
3. Check whether the model executed unauthorized downstream tools, tool arguments, or returned sensitive data.
4. Assess if persistent agent memory (Hindsight or session state) was contaminated by the payload.

## Containment Steps
1. Immediately block the attacking session/user identifier and quarantine the conversation thread.
2. If indirect injection: Quarantine the poisoned source document or URL from the RAG ingestion index.
3. If memory contamination occurred: Purge the contaminated memory entries from the active agent memory store to prevent cross-session persistence.
4. Activate strict secondary input validation and heuristic regex filters on the API gateway.

## Remediation Steps
1. Update system prompt with hardened boundary delimiters (e.g., XML tags `<user_input>` with explicit non-execution instructions).
2. Deploy semantic safety classifiers (input and output guardrails) prior to LLM inference.
3. Enforce structural separation between instructions and untrusted data in the prompt assembly layer.
4. Apply prompt fuzzing test suite against updated prompt templates before re-deploying to production.

## Verification Steps
1. Replay the attacking payload against the hardened model endpoint and verify it is intercepted and safely refused.
2. Verify normal user queries continue to execute without false-positive rejections.
3. Validate that agent memory store contains zero contaminated traces of the injection payload.

## Escalation Conditions
- Attacker successfully extracted production secrets, credentials, PII, or manipulated autonomous action execution -> Escalate to AI Security Lead & Product Security Incident Response Team (PSIRT).
