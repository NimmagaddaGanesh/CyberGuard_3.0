# Playbook PB-012: Cloud IAM Misconfiguration Response

## Purpose
Standard operational procedure for automated Tier-1 containment and Tier-2 escalation for Cloud IAM Misconfiguration.

## Detection & Indicators
- Rationale: Wildcard permissions or exposed cloud storage buckets create massive data breach and privilege escalation attack vectors.
- Priority: Critical
- Response Domain: Cloud Governance & Access Control

## Tier-1 Automated Containment
**Primary Action:** Detach overly permissive policies (*:*), restrict public storage buckets, and enforce least-privilege role boundaries.

### Tactical Execution Steps:
1. Revoke wildcard (*) administrative permissions from IAM policies and bind to scoped least-privilege roles.
2. Enable Block Public Access at the cloud organization level for all S3 and Blob storage buckets.
3. Invalidate temporary STS and cloud session tokens for affected service accounts.

## Tier-2 Alternate Escalation Playbook
**Escalation Trigger:** Tier-1 fails or analyst marks [ESCALATE].
**Alternate Action:** Infrastructure-as-Code Drift Rollback: Revert Terraform/CloudFormation to immutable baseline and enforce SCP governance guardrails.
**Escalation Tier:** Tier-2 Cloud SecOps & DevSecOps Lead

### Advanced Containment Steps:
1. Trigger CI/CD drift reconciliation to overwrite unauthorized IAM role modifications.
2. Enforce organization-level Service Control Policies blocking privilege escalations.
3. Audit cross-account trust relationships for rogue external AWS/Azure tenant IDs.

## Verification & Recovery
1. Verify indicators have ceased across SIEM/EDR streams.
2. Confirm memory writeback is recorded in Hindsight Cloud bank 'cyberguard-soc'.
3. Update Bayesian prior weights to reflect resolution outcome.
