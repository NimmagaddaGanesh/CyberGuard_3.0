# Playbook PB-014: Unsafe Tool Invocation Response

## Purpose
Standard operational procedure for automated Tier-1 containment and Tier-2 escalation for Unsafe Tool Invocation.

## Detection & Indicators
- Rationale: LLM generated tool calls with parameters violating safe boundaries or attempting filesystem/network destruction.
- Priority: Critical
- Response Domain: AI Tool Runtime Protection

## Tier-1 Automated Containment
**Primary Action:** Intercept unauthorized tool arguments, reject dangerous system calls (rm, drop, exec), and return synthetic error.

### Tactical Execution Steps:
1. Execute AST schema validation on LLM tool function call arguments.
2. Block calls attempting file system deletion, shell execution, or remote exfiltration.
3. Return synthetic error message to model preventing retry.

## Tier-2 Alternate Escalation Playbook
**Escalation Trigger:** Tier-1 fails or analyst marks [ESCALATE].
**Alternate Action:** Ephemeral Micro-VM Sandboxing: Revoke high-privilege tools permanently and isolate operations in an air-gapped micro-VM.
**Escalation Tier:** AI Platform Infrastructure Security Engineer

### Advanced Containment Steps:
1. Revoke bash/exec/eval tool capabilities permanently for the active user session.
2. Route file operations to isolated in-memory ramdisk with strict size limits.
3. Trigger security telemetry alert to LLM platform administrators.

## Verification & Recovery
1. Verify indicators have ceased across SIEM/EDR streams.
2. Confirm memory writeback is recorded in Hindsight Cloud bank 'cyberguard-soc'.
3. Update Bayesian prior weights to reflect resolution outcome.
