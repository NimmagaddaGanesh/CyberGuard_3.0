# Playbook PB-006: SQL Injection Response

## Purpose
Standard operational procedure for automated Tier-1 containment and Tier-2 escalation for SQL Injection.

## Detection & Indicators
- Rationale: Malicious SQL syntax patterns in HTTP parameters indicate an attempt to bypass auth or exfiltrate database records.
- Priority: Critical
- Response Domain: Application & Database Security

## Tier-1 Automated Containment
**Primary Action:** Deploy WAF virtual patch for identified SQL injection signatures, terminate malicious database sessions, and block source IP.

### Tactical Execution Steps:
1. Deploy Cloud WAF virtual patch filtering out SQL injection signatures on vulnerable API routes.
2. Terminate active database connection sessions originating from the attacking IP address.
3. Quarantine input field on reverse proxy and alert engineering team for parameterization.

## Tier-2 Alternate Escalation Playbook
**Escalation Trigger:** Tier-1 fails or analyst marks [ESCALATE].
**Alternate Action:** Database Exfiltration Lockdown: Restrict database service account to read-only, audit query transaction logs, and emergency patch application code.
**Escalation Tier:** Tier-2 AppSec & Database Forensics Engineer

### Advanced Containment Steps:
1. Demote database service account permissions to read-only mode to prevent table drops/modifications.
2. Audit binary transaction logs for mass exfiltration or UNION SELECT queries against sensitive tables.
3. Engage AppSec team for an emergency code hotfix deploying prepared statements and parameterized queries.

## Verification & Recovery
1. Verify indicators have ceased across SIEM/EDR streams.
2. Confirm memory writeback is recorded in Hindsight Cloud bank 'cyberguard-soc'.
3. Update Bayesian prior weights to reflect resolution outcome.
