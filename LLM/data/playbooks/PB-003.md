# Playbook PB-003: Credential Stuffing & Token Revocation

## Purpose
Procedures for identifying, throttling, and mitigating automated credential stuffing, distributed brute-force attacks on authentication endpoints, and revoking compromised tokens and sessions.

## Detection Indicators
- WAF / API Gateway alert indicating high request failure rates on `/api/login`, `/oauth/token`, or `/auth/v1/sessions`.
- Wide dispersion of source IP addresses (residential proxies, cloud ASNs) with low attempts per IP but high overall aggregate velocity.
- Low authentication success rate (< 5%) over thousands of attempts.
- Leaked credential alerts from threat intelligence feeds matching active user emails.

## Triage Steps
1. Determine the scope of targeted accounts (specific corporate domain vs general customer accounts).
2. Measure volume, geographic origin, and user-agent entropy of the traffic.
3. Identify any accounts that successfully authenticated during the stuffing burst.
4. Verify if single IP blocking or subnet rate limiting is already failing due to proxy rotation.

## Containment Steps
1. Apply adaptive bot protection / CAPTCHA challenge on the targeted authentication endpoints.
2. Implement global API rate-limiting per client fingerprint / endpoint at the API gateway layer.
3. For all accounts with successful logins during the stuffing timeframe:
   - Immediately terminate all active sessions.
   - Revoke refresh tokens, OAuth bearer tokens, and API keys.
   - Force mandatory password reset upon next login.
4. Block offending Autonomous System Numbers (ASNs) associated with known residential proxy networks if business impact is minimal.

## Remediation Steps
1. Enforce universal Multi-Factor Authentication (MFA) across all identity tiers.
2. Invalidate leaked credentials and integrate automated breached-password checking (e.g., HaveIBeenPwned API / internal bloom filters).
3. Introduce device fingerprinting and behavioral anomaly scoring before authentication authorization.

## Verification Steps
1. Confirm that bot challenge drops automated authentication attempts to baseline levels.
2. Ensure legitimate users can complete MFA challenge and re-authenticate successfully.
3. Check token revocation logs to confirm affected sessions are dead across all microservices.

## Escalation Conditions
- Compromise of executive, administrator, or privileged service accounts -> Escalate to Tier-3 IR Lead for forensic account takeover investigation.
