# Playbook PB-001: SSH Brute Force Mitigation

## Purpose
Standard operational procedure for triaging, containing, and remediating high-volume authentication failures and distributed brute force attempts against SSH endpoints.

## Detection Indicators
- SIEM alert `AUTH_SSH_FAIL_BURST` or syslog repeated `Failed password for ...` > 20 attempts in 60 seconds.
- Multiple distinct usernames attempted from single or distributed external IP addresses.
- Spike in inbound traffic on port 22 or bastion hosts.

## Triage Steps
1. Identify the targeted host(s), port, and source IP addresses from syslog/SIEM events.
2. Check if any authentication attempts succeeded (`Accepted password` or `Accepted publickey`).
3. Determine whether source IPs are isolated single subnets or distributed proxy networks.
4. Assess whether targeted accounts are privileged (root, admin, deploy).

## Containment Steps
1. If attack originates from single subnet: Apply temporary firewall drop rule or fail2ban jail on border router.
2. If attack is distributed across multiple subnets:
   - Temporarily restrict port 22 access to internal corporate VPN / bastion IP ranges only.
   - Do NOT rely solely on single-IP blacklisting (historical failure rate > 80% due to residential proxy cycling).
3. If targeted accounts are active, temporarily lock affected accounts pending verification.

## Remediation Steps
1. Enforce SSH public key-only authentication; set `PasswordAuthentication no` in `/etc/ssh/sshd_config`.
2. Enforce Multi-Factor Authentication (MFA) via PAM module (e.g., Google Authenticator, Duo).
3. Change default SSH port (optional defense-in-depth) or place host behind Zero-Trust Network Access (ZTNA) proxy.
4. Rotate SSH host keys and session tokens if unauthorized access is suspected.

## Verification Steps
1. Attempt test connection using password authentication to confirm rejection.
2. Verify SSH key + MFA flow functions for authorized administrators.
3. Monitor auth logs for 30 minutes to confirm failed attempt volume has subsided or is blocked at perimeter.

## Escalation Conditions
- Any evidence of a successful login from an anomalous external IP during the attack window -> Escalate immediately to Incident Commander as Severity: Critical (Potential Compromise).
